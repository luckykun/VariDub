## 1. 产品定位

将**中文综艺片段**一键式（但分步可控地）转换为 **3D 动画风格 + 英文配音**的短视频：

- 画面：人物/场景/构图与原视频**保持一致性**，重绘为 3D 风格（非凭空捏造）
- 声音：英文配音**复刻原说话人音色**（非通用 TTS 嗓音）
- 全程**人工可介入**：每一步产出可检查、可修改、可重跑，确认后才进入下一步

### 1.1 核心产品原则

| #  | 原则            | 落地方式                                    |
| -- | ------------- | --------------------------------------- |
| P1 | 逐步确认，拒绝黑盒一键   | 六步流水线，每步有「下一步」门禁；未确认的步骤锁定               |
| P2 | 越贵的操作，越要小样本先行 | 3D 重绘先试跑 1 张关键帧确认风格，再全量渲染               |
| P3 | 改上游比改下游便宜     | 翻译在配音前确认；配音在口型前确认；步骤⑥可跳回任意问题句           |
| P4 | 云端额度优先，本地算力补位 | 订阅内模型全走百炼 TokenPlan；订阅无能力的环节用本地开源模型（¥0） |
| P5 | 中间产物全部落盘      | 每步产物是检查点，支持断点续跑与单步重跑                    |

## 3. 核心工作流：六步流水线

```
导入视频 → [前置检查] → 确定创作 → 进入项目详情
步骤① 视频解析 → 步骤② 人声分离·识别 → 步骤③ 中→英翻译
→ 步骤④ 音色克隆配音 → 步骤⑤ 3D 画面重绘 → 步骤⑥ 口型对齐·导出
```

每步通用规则：

- 上一步「确认」前，本步按钮为锁定态（灰 + 锁标）
- 每步界面含：结果预览区（左）+ 本步骤说明/参数/模型（右侧栏）+ 底部「上一步 / 下一步」
- 每步可「换模型重跑」；产物自动存为检查点（JSON / WAV / MP4 片段）
- 云端调用失败自动重试 2 次，仍失败则标红并提示手动重跑；本地任务失败给出日志路径

### 3.1 步骤① 视频解析

| 项    | 内容                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------- |
| 输入   | 项目源视频（MP4/MOV，≤10 分钟，≥720p）                                                                     |
| 处理   | 视觉理解模型扫描全片 → 按镜头切换切分分镜 → 输出分镜表（起止时间、场景描述、出镜人物）                                                  |
| 模型   | **时段路由**：夜间(22-8点) `qwen3.8-max`（4折）/ 白天 `qwen3.8-flash`（同代视觉·省额度）；兜底 PySceneDetect（本地）。详见 §5.4 |
| 用户操作 | 预览分镜缩略网格；拖动切点手动修正；可合并/拆分分镜                                                                      |
| 产物   | `shots.json`（分镜表）+ 分镜缩略图                                                                        |
| 门禁   | 分镜表确认 → 解锁②                                                                                     |

### 3.2 步骤② 人声分离与中文识别

| 项    | 内容                                                                                    |
| ---- | ------------------------------------------------------------------------------------- |
| 输入   | 源视频音频轨 + 分镜表                                                                          |
| 处理   | ① Demucs 本地分离人声轨/背景轨；② ASR 逐句转写中文 + 说话人分离（diarization）；③ 为每位说话人自动截取并登记音色样本（≥20s 干净人声） |
| 模型   | 首选 `qwen-audio-3.0-asr-flash`（语音识别）；人声分离固定本地 Demucs                                   |
| 用户操作 | 试听双音轨；逐句校对 ASR 文字（点击试听原声）；确认说话人划分；**音色样本质量校验**——样本 <15s 或信噪比差的说话人标黄警示，可手动补选样本区间       |
| 产物   | `vocals.wav` / `bgm.wav` / `asr.json`（逐句：时间码+文本+说话人）/ `voice_samples/{speaker}.wav`   |
| 门禁   | 转写与音色登记确认 → 解锁③                                                                       |

### 3.3 步骤③ 中→英翻译（人工校对重点环节）

| 项    | 内容                                                                                                                      |
| ---- | ----------------------------------------------------------------------------------------------------------------------- |
| 输入   | `asr.json`                                                                                                              |
| 处理   | 逐句中→英翻译，系统提示注入「综艺口语风格」；输出每句备选译文 ×3；检测俚语/梗（如"下饭"）并标黄存疑；**检测英文句长超出原句时长的句子并标红**                                            |
| 模型   | **时段路由**：夜间(22-8点) `qwen3.8-max`（4折）/ 白天 `qwen3.8-flash`（4折）；手动可切 `qwen3.6-flash`（更省）。详见 §5.4                           |
| 用户操作 | 逐句编辑英文；点选 AI 备选替换；**时长超支处理**：全局策略默认「精简译文（推荐）」或「允许画面停顿」，超支句逐句人工确认二选一；**句级时间锚点拖拽**——每句显示 `起 → 止 · 时长 · 超支量`，可拖动两端锚点重设起止时间 |
| 产物   | `translation.json`（逐句：中文/英文/起止时间/处理策略/确认状态）                                                                             |
| 门禁   | 全部 34 句（示例）确认 → 解锁④；界面提示"改这里比改后面便宜"                                                                                     |

### 3.4 步骤④ 音色克隆英文配音

| 项              | 内容                                                                                    |
| -------------- | ------------------------------------------------------------------------------------- |
| 输入             | `translation.json` + 音色样本 + 音色库                                                       |
| 处理             | 每位说话人：用音色样本克隆 → 朗读确认后的英文 → 输出逐句配音 WAV（对齐句级时间锚点）                                       |
| 模型             | 首选 `qwen-audio-3.0-tts-plus`（音色复刻）；兜底本地 F5-TTS（备选，暂不实现，仅保留切换位）                        |
| 音色来源（三选一，逐说话人） | ① 本步骤克隆产物；② **音色库现成音色**（预置：Sofia/Marcus/播音员/Vivi；历史克隆）；③ 克隆后**勾选保存到音色库**（命名+标签，跨项目复用） |
| 用户操作           | 逐句试听（波形+播放）；相似度 <80% 标红 → 「重配此句」；全局参数：语速 / 音调偏移 / 情绪强度；「批量重生成」                        |
| 产物             | `dub/{line_id}.wav` + `dub_manifest.json`（逐句相似度、时长偏差）                                 |
| 门禁             | 全部句子无红标（或手动放行）→ 解锁⑤                                                                   |

### 3.5 步骤⑤ 3D 画面重绘（成本大头，两段式门禁）

| 项       | 内容                                                                                                                                                                           |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 输入      | 源视频 + 分镜表                                                                                                                                                                    |
| 处理      | **阶段①（试跑）**：选 1 个代表性分镜，重绘首帧关键帧（`wan2.7-image-pro`，人脸一致性强度默认 0.82）→ 用户对比原帧 vs 3D 帧，确认风格或调参重跑（成本几分钱）。**阶段②（全量）**：风格锁定后，逐分镜执行「关键帧重绘 + `happyhorse-1.1-i2v` 图生视频动态化」→ 输出 3D 分镜片段 |
| 模型      | 关键帧 `wan2.7-image-pro`；动态 `happyhorse-1.1-i2v`（同风格可试 `r2v`）。**无本地兜底**（显存不足，设置页已标注）                                                                                           |
| 3D 风格预设 | 皮克斯质感（默认）/ 日系动漫 / 黏土定格；参数：人脸一致性强度滑杆 0-1                                                                                                                                      |
| 用户操作    | 分镜网格逐个查看（绿=已接受 / 红=渲染中 / 灰=排队）；单分镜「接受」或「重新生成」；「重跑低一致性分镜」批量操作；每分镜显示一致性评分                                                                                                      |
| 产物      | `shots3d/{shot_id}.mp4` + `render_manifest.json`                                                                                                                             |
| 门禁      | 全部分镜接受 → 解锁⑥                                                                                                                                                                 |
| 排队策略    | 云端调用并发 ≤2（防限流）；断网续传：已完成分镜不重复计费                                                                                                                                               |

### 3.6 步骤⑥ 口型对齐与导出（成片审片器）

| 项    | 内容                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------- |
| 输入   | 3D 分镜片段 + 逐句配音 + 背景轨                                                                               |
| 处理   | ① 本地 MuseTalk 逐句驱动 3D 人物口型对齐英文音轨；② ffmpeg 合成：3D 画面 + 英文配音 + 背景音（音量 ducking）+ 双语字幕（可选烧录）            |
| 模型   | 口型：MuseTalk（本地，¥0）；合成：ffmpeg                                                                       |
| 用户操作 | **成片审片器**：完整播放；时间轴 34 句标记（绿=通过 / 黄=时长压缩 / 红=口型待修）；「上一句/下一句」跳转；口型检测报告（偏差 ms）；「查看问题句」→ 跳回对应步骤修改后重跑下游 |
| 导出设置 | 分辨率（1080p 默认）/ 帧率 30fps / 双语 SRT 开关 / 保留背景音轨开关 / 文件名                                               |
| 产物   | 成片 MP4 + SRT → 导出到「设置页指定的导出文件夹」（默认桌面）                                                              |

### 5.4 时段感知路由（Time-Aware Routing）

**动机**：清单中 qwen3.8-max / qwen3.8-flash 均标注「限时夜间 4 折」。夜间时段 max 折后价接近 flash 日常价，但质量高一档——**同样的钱，夜里买更好的模型**。

**规则（适用于环节①分镜解析、③翻译）：**

```
if 当前本地时间 ∈ [22:00, 08:00):   # 夜间折扣窗口
    选 qwen3.8-max
else:
    选 qwen3.8-flash                # 白天同代省额度
```

- **折扣窗口**默认 22:00–08:00，做成设置页可调项（若百炼官方折扣时段有变，改配置不改代码）
- **判定发生在任务提交时刻**，不追踪执行中跨时段切换
- **步骤③为人工密集环节**，用户在白天校对译文时实际调 API 的时机由「确认重生成」按钮触发——路由同样遵循上述规则，无需用户干预
- **手动覆盖**：模型下拉框始终可选任意清单内模型（含 qwen3.6-flash / deepseek-v4-pro 等）；时段路由只是「自动」选项的行为
- **UI 表达**：步骤①③的模型行显示当前生效模型 + 折扣角标，如 `qwen3.8-max · 夜间4折生效`（白天显示 `qwen3.8-flash · 标准计价`）
- 不适用范围：audio 系列（ASR/TTS）无折扣标注，固定单模型；wan/happyhorse 视频类无折扣标注，不做时段路由

**配置项（Settings 表）**：`route.time_aware=true`、`route.discount_window="22:00-08:00"`

## 6. 数据模型（SQLite 单库）

```
Project   id, name, source_video_path, duration, status(current_step/step_state),
          created_at, updated_at
Shot      id, project_id, index, start_ms, end_ms, scene_desc, style_id,
          consistency_score, accept_status          -- 步骤①⑤
Line      id, project_id, shot_id, speaker_id, start_ms, end_ms,
          zh_text, en_text, en_alts(json), overflow_policy(none/compress/freeze),
          confirm_status, dub_wav_path, similarity   -- 步骤②③④
Speaker   id, project_id, label, sample_wav_path, sample_quality,
          mapped_voice_id → VoiceLibrary.id
Voice     id, name, source_type(preset/cloned), origin_project_id,
          tags, sample_path, ref_count               -- 音色库
Artifact  id, project_id, step, kind, path, created_at  -- 检查点索引
Settings  key, value    -- api_key(系统级加密存储), 模型路由(每环节), 时段路由开关+折扣窗口,
                          导出文件夹(默认桌面), 3D风格与人脸一致性参数, 全局翻译风格指令
```

**检查点目录**：`D:/Vardub_Workspace/{project_id}/`（分镜子目录、音轨、逐句 WAV、3D 片段、日志）。

## 7. 技术架构与工程实现

### 7.1 架构总览

```
┌─────────────────────────────────────────────┐
```

### 7.5 进程间通信契约

| 通道                      | 方向                   | 内容                                                              |
| ----------------------- | -------------------- | --------------------------------------------------------------- |
| REST `/api/*`           | 渲染层 → 主进程 Fastify    | CRUD 项目/句/音色/设置；启动步骤任务（返回 taskId）                               |
| SSE `/api/events`       | 主进程 → 渲染层            | 任务进度流：step 状态、云端任务轮询进度、GPU 队列占用、日志尾行                            |
| IPC（contextBridge）      | 渲染层 ↔ 主进程            | 原生目录选择框、文件"在资源管理器中显示"                                           |
| HTTP `127.0.0.1:{随机端口}` | 主进程 → Python sidecar | `/separate`（Demucs）、`/lipsync`（MuseTalk）；主进程负责 sidecar 的启停与崩溃拉起 |
| GET `/api/files?p=` | 渲染层 `<video>`/`<audio>`/`<img>` | 本地媒体流，必须支持 Range（206），路径限项目工作区 / 源视频目录 / 导出目录 |

规则：渲染层**永不**直接触文件系统与网络 API（除 localhost）；所有副作用收敛在 server 层，便于单测。

**媒体流两条硬约束**（踩过的坑：状态码与响应头全对、body 却是 0 字节，于是视频控件渲染出来了却永远放不出来）：

1. `streamFile` **必须同步返回 `FastifyReply`，调用方必须写 `return streamFile(...)`** —— 不做成 `async`、也不 `await`。Fastify 在 async 处理器定下来时若发现 reply 尚未标记为已发送，就用处理器的返回值（`undefined`）收尾，流被丢弃。
2. **Range 语义要完整**：`bytes=a-b`、`bytes=a-`、`bytes=-N`（最后 N 字节，不是前 N 字节）、越界回 `416 + Content-Range: bytes */size`、看不懂的 Range（多段合并）回整文件 200。非 faststart 的 mp4 把 moov 写在文件末尾，播放器拿不到尾部字节就报「无可用源」，因此只回 200 全量是不够的。另：允许目录判定（`within`）在 Windows 上**不区分大小写**，否则对话框给的 `C:\…` 与设置里填的 `c:\…` 会误判 403。

### 7.6 设计还原与 Token 映射（保真原则）

设计稿是**视觉基准而非像素合同**（用户已确认：未对齐/细节瑕疵按正常工程实现，不强行还原）。固定为 token 的部分：

```ts
// theme.ts —— 从设计稿提炼，实现时唯一颜色来源
colors: {
  canvas:'#181818',            // 一切「正常态」的唯一底色
  elevated:'#303030',          // 只给「高亮相关」：hover / 选中 / 聚焦 / 滑杆进度槽
  hairline:'#303030',          // 描边分层用，不靠底色
  ink:'#FFFFFF', body:'#A8A8A8', muted:'#666666',   // body 是全站默认文字色；设计稿基准 #969696，因长时间阅读费力按用户反馈上调一档
  accent:'#DA291C',            // 主行动/当前步骤/危险操作描边
  success:'#03904A', warn:'#F6E500', error:'#F13A2C', info:'#4C98B9',
}
radius: { none:0, input:4, pill:9999 }   // 直角为主，仅输入框 4px
spacing: [4,8,16,24,32,48]               // 4px 基准阶梯
controlH: 32                              // 单行控件统一高度（theme.css 发 --control-h）
panelHeaderH: 48                          // 卡片 Header 统一高度（--panel-header-h）
barH: 56                                  // 贴底横条统一高度：步骤 Footer 与菜单底栏共用（--bar-h）
fonts: {
  ui:      'Noto Sans SC, system-ui',    // 中文界面
  display: 'Inter, Noto Sans SC',        // 数字/英文标题
  mono:    'JetBrains Mono, Consolas',   // 时间码/模型名/路径
}
```

**明暗层级（不可反）**：正常态一律黑（画布、顶栏/侧栏/底栏、卡片、按钮、输入框、徽章），彼此靠 `hairline` 描边区分；灰 `elevated` 只在高亮相关处出现（悬浮、选中/当前项、聚焦描边、滑杆与进度槽）。曾出现「整片灰底 + 选中项变黑」的反向实现，已纠正。

**hover 反馈不得掉色**：灰底只给无主色的默认/幽灵按钮。红色主按钮（`.btn-accent`）hover 必须自己重声明 `background-color: var(--color-accent)`，只用 `filter: brightness(1.15)` 提亮 —— 它与 `.btn:hover` 同权重（类+2 个伪类），只靠后声明的边框/提亮管不到背景，鼠标一放红底就变灰。新增带主色的按钮变体同理：写变体 hover 时背景、边框、文字三样都要显式声明，不能指望基类 hover 规则「不覆盖」（基类会覆盖它）。

**滚动条约定（一屏只允许一条）**：卡片内不得再嵌一层 `overflow` 滚动（`Panel bodyScroll={false}`）；内容超过一屏时只允许页面内容区滚一次。设置页因此改为 Tab 分组 + 卡内左右两栏排布，而不是一屏堆五张卡。步骤工作区（`StepPane`）同理：左右两栏都按内容自然撑高，整条工作区只有一条滚动条；右栏卡片（本步骤说明 / 运行本步骤 / 统计）**不得设最大高度** —— 曾用「最大高度 58% + 内部滚动」把「运行解析」按钮整块裁到可视区外，用户完全找不到运行入口。日志卡固定 300px 且内部自滚（事件流是列表，不属于内容卡）。

**媒体预览高度**：左栏视频用 `w-full` + `max-h-[min(56vh,520px)]` 按源片宽高比自然撑高（16:9 源在 1460×920 下约 480px），不得再用 240px 这类死高 —— 视频被压成横条会让整个预览区看起来「扁」。

**保存栏约定（一卡一栏、独占一行）**：设置页每张卡只有底部一条保存栏（`SaveRow`，上描边 + 贴齐卡片左右与底边），保存按钮不得夹在字段行里；栏内右侧用 `DraftState` 给出本组脏状态（黄 = 有未保存修改，与「黄待办」语义一致）。“改一个字段就有一个保存按钮”属于旧布局，已收敛；不需要保存按钮的项（目录选择、sidecar 路径/端口、Mock 开关）保持改动即时生效，并在栏内用文字注明。

**自绘控件约定（夺了外观就要自己补图形）**：只要写了 `appearance: none`，Chromium 就不再画内置状态图形，必须自己补上。checkbox 选中态 = 红底 `accent` + 白色对勾（内联 SVG，`viewBox 0 0 10 10`、`stroke-width 2`、`background-size 10px`，在 14px 框里 1:1 不虚），仅给红底不画勾是错误实现（曾出现“实心红块”）；新增 radio / switch / 多选类控件同理，且必须同时给 hover 描边与 disabled 态。

**控件高度（单行控件一律 `--control-h: 32px`）**：`.btn`、单行 `input`、`select`、设置页 Tab 条同高，靠 flex 居中而不是上下内边距撑高，改高度只改这一个 token。不参与统一高度的：`.btn-sm`（卡片行内的紧凑小按钮）、多行 `textarea`、缩略图/图标类按钮、侧栏菜单行与窗口标题栏。

**线条对齐（Header 与贴底横条一律定高）**：卡片 Header 统一 `--panel-header-h: 48px`，内容垂直居中，不许再跟着内容走 —— 标题有 12/13px 两档、右侧可能放徽章或行内小按钮，自然高度实测在 43〜57px 之间散开，卡片并排时上描边全部错位。定高必须同时给标题列 `min-w-0 + truncate` 兜底（宁可省略号也不让文字探出卡外），并在最窄窗口下复验：1460×920 与 1160×720 两档下 49 个卡头均为 48px、无溢出、无标题被截。同理，步骤工作区的 Footer 与左侧菜单底栏取同一个 `--bar-h: 56px` 并都贴底，两条上描边才落在同一水平线上（Footer 原先用 `py-3` 撑高，遇阻塞/提醒多一行就从 57 涨到 63.5，而菜单底栏又是 59，三条线互相对不上）。定高后 Footer 中间提示列需 `overflow-hidden`，提醒文本本身带 `title` 全文作为补偿。

**光标（可点必手指）**：全局规则包打，新增按钮不需再单独写光标 —— `button:not(:disabled)` / `[role=button]` / `[role=tab]` / `a[href]` / `summary` / `select` / checkbox / range / `label:has(input)` 一律 `cursor: pointer`；`button:disabled` 为 `not-allowed`；文本框保持 `text`（写在 label 规则之后，不被外层手指光标掩盖）。可点 div/行（如音色卡、导出句表行）仍需在组件上显式加 `cursor-pointer`。

**允许偏离**：栅格具体间距 ±4px、组件投影（设计稿无阴影，实现同样不加，用亮度分层）、文案微调。  
**必须一致**：状态色语义（绿完成/红当前与危险/黄待办警示）、步骤条三段态、门禁锁定态视觉（灰+锁）、直角主风格。

### 7.7 关键实现约束

1. wan2.7-image-pro / happyhorse-1.1-i2v 是**异步任务 API**——提交后轮询（间隔 5s 起指数退避，上限 60s），编排器需处理任务排队、超时（单任务 >15min 判失败）、结果下载、断点恢复（taskId 持久化到 Artifact 表，重启后先查未完成 task 再决定是否重提交，**避免重复计费**）
2. 句级时间锚点（步骤③人工设定）是**全链路真值**：配音对齐、字幕、口型窗口全部引用它；锚点修改后下游产物标记 stale，UI 提示重生成
3. 本地任务（Demucs/MuseTalk）写日志到项目目录 `logs/`，UI 内可查看尾 200 行
4. GPU 串行锁：`gpuQueue` 全局唯一消费者；sidecar 崩溃自动重启一次，仍失败则任务置 error 并提示
5. 时段路由（§5.4）在 `timeRouter.ts` 单点实现，所有 chat/vision 调用必须经过它取模型名，禁止散落的 if 判断
6. 并发上限：百炼异步任务同时进行中 ≤2（防限流），在 `asyncTask.ts` 内置信号量

1. **exe 是快照**：改了源码不重跑 `npm run dist`，双击看到的还是旧界面 —— 调 UI 请用菜单 [3] 开发模式（热更新，无需打包）。
2. **单实例锁挂在 `userData`**：`VARIDUB_DATA_DIR` 必须同时 `app.setPath('userData', …)` 才能并行多开；点窗口 × 只是收进托盘（进程仍在），此时再双击会被锁挡掉 —— 现在 `second-instance` 会比对两边 exe 路径并弹框说明。
3. **中文不能写进 `.bat`**：cmd 按字节定位批处理行，中文与控制台代码页（本机 936）不一致就错位，把 `rem` 当命令执行（报 `'ectron-vite' is not recognized`）；而把 bat 存成 GBK 又会被按 UTF-8 打开的编辑器回写成乱码（实测出现「锟斤拷」+ U+FFFD）。最终约定：**`.bat` 永远纯 ASCII**，中文提示一律放 `scripts\launch.ps1`（PowerShell 走 Unicode API 写控制台，与代码页无关；但**必须带 UTF-8 BOM**，否则 PS 5.1 会按 ANSI 读成乱码）。启动器还会在旧实例在跑、以及「源码比 exe 新」时主动提醒。

Mock 判定单点：`isMock()`（env `VARIDUB_MOCK=1` 或设置表 `api.mock`）。`--mock` 只影响本次进程、不写库；否则跑过一次自检后，下次正常启动仍被当成正式版其实在出假产物。

### 7.9 选型理由（评审点 R1）

- **Electron + React**：设计稿是标准 Web 视觉语言，还原成本最低；自用无需在意包体积与内存占用
- **Node 编排 + Python sidecar**：Demucs/MuseTalk 生态全在 Python，隔离成子进程避免 torch 依赖污染 Node 工程；GPU 任务全局串行锁是 16GB 内存 + 6GB 显存约束下的硬规则
- 备选 Tauri：更轻但 Rust 侧生态弱、ffmpeg/python 集成反而更繁琐——自用场景收益为负，不选
- API-KEY 存储：Electron `safeStorage`（Windows 凭据管理器 DPAPI），不落明文

## 8. 非功能需求

| 项    | 要求                                      |
| ---- | --------------------------------------- |
| 断点续跑 | 应用崩溃/重启后，项目恢复到当前步骤的未完成点；云端已付费产物不重复生成    |

| 版权提示 | 新建项目对话框底部一行小字：仅供个人学习使用，勿传播侵权内容（一次性，可关闭） |
| 性能   | 4 分钟片段全流程（不含渲染等待）人工操作时间目标 < 40 分钟       |
